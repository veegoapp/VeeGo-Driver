Fix 1 — B1: Remove duplicate shuttle:referral:incoming listener

Problem:
The event shuttle:referral:incoming is currently handled twice:
1. ReferralSocketBridge in app/_layout.tsx
2. useShuttleSocket.ts inside the shuttle route group

This causes duplicate referral queue entries and duplicate badge counts.

Action:
Keep only one active listener.
Prefer keeping the shuttle-specific handling inside useShuttleSocket.ts.
Remove the duplicate listener from ReferralSocketBridge or otherwise ensure only one handler exists.

Verify:
- shuttle:referral:incoming fires exactly once.
- No duplicate addIncomingReferral calls remain.


Fix 2 — R2: Ensure ShuttleProvider exists during ActiveSession cold-start recovery

Problem:
When the app restarts during an active shuttle trip:
ActiveSession redirects directly to /shuttle/trip-active.
The ShuttleProvider from (shuttle)/_layout.tsx may not be mounted.
This leaves ShuttleContext values empty:
- activeLine
- stops
- passengers
- stationCoords
- nextStop

GPS recovery works, but operational trip data can be missing.

Action:
Move ShuttleProvider to a parent scope where it is guaranteed to exist during cold-start recovery.
Do not break existing shuttle screens.
Keep current ShuttleContext API unchanged.

Verify:
- Opening the app during an active shuttle trip restores:
  - stops
  - passengers
  - station data
  - trip controls


Fix 3 — R1: Add ride socket event fallback for phase updates

Problem:
Ride screen currently registers:
- ride:status:changed
- ride:driver_assigned
- ride:driver_arrived
- ride:started

but handlers do nothing.

Action:

Verify:
- Ride phase updates correctly even if snapshot delivery is delayed.
