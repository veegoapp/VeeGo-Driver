Task: Design a unified navigation experience architecture for the VeeGo Driver App similar to Uber/Careem driver navigation.

IMPORTANT:
- Do NOT modify any code.

- Only inspect the current codebase and provide a detailed technical plan.

Context:
VeeGo Driver App supports multiple services:
- Ride
- Scooter
- Delivery
- Shuttle

The goal is NOT to build a full Google Maps navigation system with voice instructions.
The goal is an Uber/Careem-style driver navigation experience.

Required navigation experience:

1. Navigation Camera:
- Follow the driver's vehicle position.
- Rotate camera based on driver heading/bearing.
- Use a tilted perspective (pitch).
- Maintain appropriate zoom.
- Keep the vehicle positioned slightly lower on the screen (look-ahead style).
- Smooth camera movement while driving.

2. Route Display:
Ride:
- Before pickup:
  Driver → Passenger pickup location.
- After pickup:
  Driver → Destination.

Shuttle:
- It is acceptable to show the complete fixed route between stations.
- However, the driver should still have active navigation behavior:
  - Vehicle marker movement.
  - Follow camera.
  - Bearing rotation.
  - Ability to navigate between stations.

Scooter and Delivery:
- Should follow the same navigation architecture.

3. Route Management:
- Use a consistent route-fetching strategy across all services.
- Avoid having Map components responsible for business logic or API calls.
- Map components should mainly render:
  - Map
  - Route polyline
  - Vehicle marker
  - Camera behavior

4. Rerouting:
Investigate the best approach for:
- Detecting when the driver leaves the route.
- Requesting a new route from the current driver location.
- Whether the existing Directions API integration is enough.

5. Smooth Driver Movement:
Investigate:
- Current GPS update frequency.
- Marker animation.
- Heading smoothing.
- Camera animation timing.

6. Route Progress:
Evaluate whether VeeGo should implement:
- Remaining route only.
- Removing completed route segments.
- Keeping the full route visible.
